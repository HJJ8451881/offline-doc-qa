# 專案規格：offline-doc-qa

> 用途：作品集 repo。目標是讓面試官在 5 分鐘內看懂「這個人能一人把 LLM 系統從零做到可跑」。
> 把這份文件放進空 repo 的 `_doc/v1.0.md`，然後對 Claude Code 說：「請依照 `_doc/v1.0.md` 實作這個專案」。

---

## 一、專案目標

一個可本機運行的文件問答系統：上傳 PDF → 解析 → 切塊 → 向量化 → 檢索 → 由本地 LLM 生成回答，並標示引用來源。

全部離線，不呼叫任何雲端 API。這是這個專案的核心賣點。

## 二、技術棧（不要替換）

| 層 | 選型 | 理由 |
|---|---|---|
| 推論 | Ollama | 本地模型部署 |
| 後端 | FastAPI | Python 後端 + API |
| 向量庫 | PostgreSQL + pgvector | 生產級向量檢索 |
| PDF 解析 | PyMuPDF | 純 Python，無外部二進位相依 |
| 前端 | 單一 HTML 檔（原生 JS，無框架） | 免建置流程，clone 完直接能跑 |
| 部署 | Docker Compose | 一行指令起整套 |

Embedding 用 `nomic-embed-text`，對話用 `qwen2.5:7b`（都可由環境變數覆寫）。

## 四、模組職責

**config.py** — `Settings(BaseSettings)`，欄位：`ollama_base_url`、`embed_model`、`chat_model`、`postgres_*`、`chunk_size`(500)、`chunk_overlap`(80)、`top_k`(5)。用 `@lru_cache` 提供單例。不要用全域變數。

**ingest.py**
- `extract_pages(pdf_bytes: bytes) -> list[Page]`：PyMuPDF 逐頁抽文字，保留頁碼（引用要用）。
- `chunk_text(text: str, size: int, overlap: int) -> list[str]`：滑動視窗切塊，優先在句號/換行斷開，避免切碎句子。
- 兩個函式都是純函式、不碰 I/O，方便測試。

**embeddings.py** — `async def embed(texts: list[str]) -> list[list[float]]`，呼叫 Ollama `/api/embeddings`。用 `httpx.AsyncClient`，包 try/except 並 log 失敗，逾時設 60 秒。

**store.py** — `psycopg` 連線池。方法：`insert_chunks()`、`search(query_vec, top_k)`（用 `<=>` cosine 距離）、`list_documents()`、`delete_document()`。SQL 一律用參數化查詢。

**rag.py** — `async def answer(question: str) -> Answer`：embed 問題 → 檢索 top_k → 組 prompt → 呼叫 Ollama `/api/chat` → 回傳答案與來源。Prompt 要明確要求「只根據提供的內容回答，資料不足就說不知道」。

**main.py** — 端點：
- `POST /api/documents`（上傳 PDF，multipart）
- `GET /api/documents`
- `DELETE /api/documents/{doc_id}`
- `POST /api/ask` → `{answer, sources: [{doc_name, page, snippet, score}]}`
- `GET /api/health`（順便回報 Ollama 是否連得上）
- 靜態檔掛在 `/`

**index.html** — 左側上傳與文件清單，右側問答。回答下方列出來源（檔名 + 頁碼 + 片段）。原生 JS + fetch，不用任何框架或 CDN。樣式簡潔即可，但不要醜。

## 五、資料庫

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE documents (
    id UUID PRIMARY KEY,
    filename TEXT NOT NULL,
    page_count INT NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE chunks (
    id BIGSERIAL PRIMARY KEY,
    document_id UUID REFERENCES documents(id) ON DELETE CASCADE,
    page_no INT NOT NULL,
    content TEXT NOT NULL,
    embedding vector(768)
);

CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
```

維度 768 對應 `nomic-embed-text`。README 要註明換模型時要改這個數字。

## 七、測試

`test_ingest.py` — 切塊邏輯：長度符合、overlap 正確、短文本不會產生空塊、中英混排不會切壞。
`test_rag.py` — 用 fake embedding client 與 fake store，驗證檢索結果有正確組進 prompt、來源有回傳。不要為了讓測試過而寫死回傳值。

## 八、README（這是最重要的產出）

面試官只會看 README。必須包含：

1. **一句話說明**：可完全離線運行的本地文件問答系統，用於機密文件不可外傳至雲端的情境。
2. **架構圖**：Mermaid flowchart，畫出 PDF → PyMuPDF → chunk → Ollama embed → pgvector → 檢索 → LLM → 回答。
3. **Demo 截圖**：留 `docs/screenshot.png` 的位置，實際跑起來後補上。
4. **快速開始**：三行指令（`cp .env.example .env` → `ollama pull` → `docker compose up`）。
5. **設計決策**（用表格，每項一句話說明取捨）：
   - 為何選 pgvector 而非 Chroma／FAISS（既有 PG 維運、可與業務資料同庫、支援權限過濾）
   - 為何 chunk 500 / overlap 80
   - 為何要保留頁碼（引用可追溯，是企業內部使用的必要條件）
   - 為何前端不用框架（降低 clone 後的啟動門檻）
   - 模型選型與 VRAM 的取捨
6. **已知限制**：只支援文字型 PDF（掃描檔需 OCR）、單機單使用者、無權限控制。**誠實列出限制比假裝完美更能取信於人。**
7. **後續可擴充**：OCR、多使用者權限隔離、混合檢索（BM25 + 向量）、reranker。

README 用中文寫，技術名詞保留英文。
